# AutoList UI/UX 审计

审计版本：`1.02` 当前基线
审计日期：2026-08-09
审计范围：工作台、片单、资源搜索、下载列表、候选规则、下载历史、站点与服务、日志 8 个路由；桌面端、窄屏和横屏导航；弹窗、空状态、键盘交互、错误播报、候选分组和静态资源。

## 当前结论

AutoList `1.02` 的视觉方向已经稳定：银盐雾灰背景、暗房碳黑文字、放映机蓝主色和胶片琥珀状态色形成清晰层级。工作台承担总览，片单、搜索、下载列表、候选规则、历史、站点和日志保持独立路由，页面刷新、前进和后退可以恢复路由状态。

本基线不建议整体换肤。当前优先级是保持候选信息的分组辨识度、保证移动端交互可达、让异步失败有可恢复路径，并在应用代码变更后继续做真实浏览器回归。

## 已关闭或当前有效的体验问题

### 1. 候选影片分组辨识度 — 已关闭（1.02）

影片组起始行使用醒目的深色横向分隔线和更大的组间距，左侧保留蓝色分组标识；橙色只表达“首选”状态，不再承担主要结构分隔。候选列表中的同影片资源保持细分隔线，跨影片边界使用粗分隔线。

### 2. 页面与移动导航 — 当前有效（1.02）

8 个路由可以直接访问并通过 hash 刷新恢复；桌面端、390×844 窄屏和 844×390 横屏回归未发现横向滚动；移动抽屉支持 Escape、焦点返回与基本焦点约束。浏览器控制台未发现当前基线相关的 error 或 warning。

### 3. 弹窗和服务状态 — 当前有效（1.02）

设置、站点和确认类弹窗具备标题关联、关闭路径和敏感字段“已配置”语义；设置页不会把已脱敏的 API Key 当成未配置。服务状态、任务进度和站点检测结果使用可读的中文摘要，失败不会直接向界面暴露原始异常堆栈。

### 4. Logo 与品牌资源 — 当前有效（1.02）

Logo、favicon 和 Unraid PNG 图标均随镜像提供：Web 资源通过 `/assets/logo.svg`、`/assets/favicon.svg` 访问，镜像构建阶段把 `unraid/autolist-icon.png` 复制到 `/app/app/static/autolist-icon.png`，因此容器运行后也可通过 `/assets/autolist-icon.png` 访问。Docker/Unraid 图标资源采用固定 commit URL，避免依赖可变的 `main` 分支；源码直接启动的开发服务不承诺提供该构建期复制资源。

## 1.02 应用代码修复结果

以下问题已在 `app` / `app/static` 范围内修复，并通过静态检查、101 项自动化测试和隔离浏览器回归复核。

### 1. 中间宽度候选列的静态裁切风险 — 已关闭（1.02）

`app/static/style.css` 已移除全局 `overflow-x: clip`，并为 901–1160px 增加可收缩的 `minmax(0, 1fr)` 网格；搜索表单、候选列在 1024px 实测无横向溢出。

### 2. 文件导入的键盘可达性 — 已关闭（1.02）

文件 input 改为视觉隐藏而非 `display:none`，label 支持 `focus-within`，并补充 `aria-label` 与文件提示文本。

### 3. 异步操作失败恢复 — 已关闭（1.02）

重命名、同步、排序、展开和删除等动作已统一增加 loading/disabled、`catch`、超时和恢复语义；候选、识别、媒体库轮询失败时显示错误和手动重试入口。

### 4. DOM 重绘与焦点保持 — 已关闭（1.02）

候选轮询使用渲染签名避免无意义重绘，并在必要重绘时恢复 `details` 展开状态、滚动位置和焦点；动态结果区域补充 `aria-live`、`role="progressbar"` 和可计算进度值。

### 5. 过滤器和动态控件语义 — 已关闭（1.02）

站点筛选已与明确的 `tabpanel`、`aria-controls` 配对；片单卡片展开按钮指向明细面板；历史列表超过 50 条时展示“仅显示最近 50 条”的明确提示。

## User-Agent 版本说明

站点适配器的自定义 User-Agent 可在界面配置；未配置时由 `app/config.py` 的应用版本常量生成 `AutoList/1.02`，不再使用历史 `AutoList/0.65` fallback。

## 验证基线

- 1.02 发布回归覆盖 8 个页面路由、桌面端、320/375/390px 窄屏和 844×390 横屏；重点检查导航、弹窗、空状态、候选分隔、Logo 资源和横向溢出。
- 浏览器控制台在已验收页面未发现 error 或 warning；未执行真实下载提交。
- 静态检查基线：`python3 -m compileall -q app`、`node --check app/static/app.js`、`node --check app/static/js/core.js`、101 项 unittest 通过。
- Docker healthcheck 只验证本地应用和 SQLite；它不是 TMDB、PT、Emby、Transmission 或 MoviePilot 的 UI/业务验收。

## 后续 UI 验收门槛

每次修改 `app` 或 `app/static` 后，应重新打开全部 8 个路由，并至少在桌面、390×844、768×1024 和 844×390 检查：

1. 页面加载、路由刷新、前进后退和滚动位置。
2. 设置、站点、导入、确认弹窗的打开、关闭、Escape、焦点返回和错误状态。
3. 搜索、候选轮询、下载列表、历史筛选和空状态。
4. `document.documentElement.scrollWidth` 是否超过视口宽度。
5. 控制台 error、失败网络请求、按钮重复点击和异步失败后的恢复。
