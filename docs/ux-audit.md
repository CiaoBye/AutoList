# AutoList UI/UX 审计

审计版本：0.73（基线） / 0.79（回写）  
审计日期：2026-07-26  
审计范围：工作台、片单、资源搜索、下载列表、下载历史的核心闭环；桌面端与 390×844 移动端。

## 结论

现有“银盐雾灰 + 暗房碳黑 + 放映机蓝/胶片琥珀”的视觉方向稳定，信息层级和页面分区已经具备产品辨识度，不需要整体换肤。桌面和移动端核心页面均通过无横向溢出检查；移动端底部导航、空状态入口和页面路由可用；浏览器控制台没有错误。

0.74 已优先补齐闭环状态与失败恢复；0.75 聚焦安全基线（访问令牌、CookieCloud 绑定）与工程闸门。后续仍以可访问性细节与可选体验提升为主，不需要整体换肤或重做布局。

## 必须修复（0.74 状态）

### 1. 下载历史没有展示下游状态 — **已关闭（0.74）**

已实现来源驱动生命周期：已提交、下载中、已整理/已入库、待入库、待确认、失败；工作台最近活动复用同一投影。

### 2. 站点失败信息仍是原始异常文本 — **已关闭（0.74）**

搜索失败转为中文可执行摘要，技术细节保留在日志；提供重试失败站点 / 重新搜索整项。

### 3. 部分完成任务缺少完整重启入口 — **已关闭（0.74）**

部分完成、失败、中断任务均可区分“重试失败站点”与“重新搜索整项”。

### 4. 错误与任务更新的辅助技术语义不足 — **部分关闭（0.74）**

已补任务状态播报、错误摘要与部分 `aria` 关联；持续以屏幕阅读器与键盘路径做回归。

## 建议优化

### 5. 补齐部分表单控件的可访问名称 — **部分推进（0.74）**

片单明细、候选规则等控件已补部分标签；若发现遗漏控件，按页补齐可见 `<label>` 或 `aria-label`。

### 6. 为弹窗建立标题关联 — **部分推进（0.74）**

导入、确认下载、设置、站点等弹窗已按 CHANGELOG 补标题关联；新弹窗需沿用同一模式。

### 7. 统一闭环文案 — **已关闭（0.74）**

下载历史副标题改为追踪提交/下载/入库；“重新搜索整项”替代含糊的“重新启动”。

### 8. 移动端保留服务状态的可见摘要 — **部分推进（0.74）**

窄屏保留服务在线数摘要；若布局回退，优先保证计数可见且不横向溢出。

## 可选提升

- 候选空状态、提交摘要、历史状态筛选、本机令牌管理：已在 0.78–0.79 关闭。
- 仍可继续：按影片展开下游状态详情、更细的历史分页（当前截断 50 条展示）。

## 0.75 安全相关界面影响

- 启用 `AUTOLIST_ACCESS_TOKEN` 后，未带令牌的 `/api/*` 返回 401；前端弹窗收集令牌并写入 `localStorage`。
- CookieCloud 扩展 KEY 必须与 AutoList 设置中的 KEY 一致，否则上传被拒绝。
- 搜索并发达上限时接口返回 429，界面应展示服务端错误文案。

## 验证基线

- UI Pro Max 检索重点覆盖错误恢复、错误播报、提交反馈、加载反馈、进度指示、移动端表格和 viewport。
- 生产页面桌面端检查了工作台、资源搜索、下载列表、下载历史；移动端检查了工作台、片单、资源搜索、下载列表、下载历史。
- 390×844 下 `document.documentElement.scrollWidth` 未超过视口宽度；核心页面没有横向溢出。
- 浏览器控制台未发现 error 或 warning。
- 0.75 代码侧：`compileall`、`node --check`、`unittest`；浏览器全页回归依赖部署后人工确认。
