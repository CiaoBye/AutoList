# AutoList UI/UX 审计

审计版本：0.73  
审计日期：2026-07-26  
审计范围：工作台、片单、资源搜索、下载列表、下载历史的核心闭环；桌面端与 390×844 移动端。

## 结论

现有“银盐雾灰 + 暗房碳黑 + 放映机蓝/胶片琥珀”的视觉方向稳定，信息层级和页面分区已经具备产品辨识度，不需要整体换肤。桌面和移动端核心页面均通过无横向溢出检查；移动端底部导航、空状态入口和页面路由可用；浏览器控制台没有错误。

下一步应优先补齐闭环状态和失败恢复，而不是增加装饰或重做布局。当前页面把“已提交”作为下载历史的主要事实，但用户真正需要知道的是资源现在处于提交、下载、待确认还是已入库中的哪一步。

## 必须修复

### 1. 下载历史没有展示下游状态

现状：历史记录只显示成功/失败，成功记录统一显示“已提交”；工作台最近活动也只显示“已提交”。这不能回答“是否正在下载”或“是否已经整理进 Emby”。

目标：为每条记录提供来源明确的状态：已提交、下载中、已整理/已入库、待确认、失败，并在状态不确定时说明原因或下一步。

### 2. 站点失败信息仍是原始异常文本

现状：搜索日志显示类似 `[Errno -2] Name or service not known`，虽然没有泄露凭据，但用户无法直接判断是 DNS、站点地址还是登录问题。

目标：界面显示可理解的错误摘要和恢复动作；技术细节保留在可展开日志中。错误消息必须带“重试失败站点”或“重新搜索整项”等下一步。

### 3. 部分完成任务缺少完整重启入口

现状：部分完成任务主要显示“重试失败站点”；“重新启动”对部分完成状态隐藏，无法从同一处重新搜索整项。

目标：部分完成、失败和中断任务都能明确区分“重试失败站点”和“重新搜索整项”，并保留当前任务上下文。

### 4. 错误与任务更新的辅助技术语义不足

现状：任务日志和下载历史更新区域没有 `aria-live`；失败信息主要依赖视觉颜色和展开日志。

目标：状态变化、错误摘要和恢复结果可被屏幕阅读器感知；颜色不是唯一状态信号。

## 建议优化

### 5. 补齐部分表单控件的可访问名称

当前源码中片单明细搜索框、候选规则的分辨率下拉框和标题试算输入框缺少明确的关联标签。应使用可见 `<label>` 或等价的 `aria-label`，并保持现有中文文案。

### 6. 为弹窗建立标题关联

现有导入、确认下载、设置和站点弹窗都有可见标题，但没有 `aria-labelledby` 关联。补齐后可改善键盘和屏幕阅读器导航，不改变视觉布局。

### 7. 统一闭环文案

下载历史页当前副标题“查看已提交资源”会强化“提交即完成”的误解。建议改成“追踪提交、下载与入库状态”，并把“重新启动”改成更明确的“重新搜索整项”。

### 8. 移动端保留服务状态的可见摘要

当前窄屏把顶部服务状态收缩为彩色圆点。按钮仍有可访问名称，但视力正常的用户无法直接看到 `4/4` 和服务异常摘要。建议在不增加横向占用的前提下保留简短计数或异常标记。

## 可选提升

- 候选为空时，根据任务状态显示“无可下载候选”“站点搜索失败”或“等待搜索”，并直接提供对应恢复入口。
- 下载列表提交成功后，在页面内保留短暂的状态摘要，说明已提交数量和后续会由谁（MoviePilot、Transmission、Emby）确认。
- 为下载历史增加状态筛选或按影片展开下游状态详情；本轮不要求新增复杂筛选器。

## 验证基线

- UI Pro Max 检索重点覆盖错误恢复、错误播报、提交反馈、加载反馈、进度指示、移动端表格和 viewport。
- 生产页面桌面端检查了工作台、资源搜索、下载列表、下载历史；移动端检查了工作台、片单、资源搜索、下载列表、下载历史。
- 390×844 下 `document.documentElement.scrollWidth` 未超过视口宽度；核心页面没有横向溢出。
- 浏览器控制台未发现 error 或 warning。
